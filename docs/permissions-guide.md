# 嘉壹启航 · 权限体系说明

> 更新日期：2026-08-09  
> 权威源码：`backend/app/core/permissions.py`  
> 前端常量：`frontend/src/constants/permissions.ts`（须与后端 code 一致）  
> 菜单：`frontend/src/composables/useAppMenus.ts`  
> 数据范围：`backend/app/core/roles.py`

本文供 **产品/负责人分析角色是否合理**，以及 **开发改权限时对照**。

---

## 0. 三条铁律

1. **权限码是业务开关**  
   菜单、路由、按钮、接口都应挂 **code**，不要只靠「是不是运营」硬编码（数据范围除外）。

2. **有效权限 = 角色自带 ∪ 额外授权**  
   | 概念 | 含义 |
   |------|------|
   | **角色自带** | 选角色后自动拥有，授权弹窗里标「角色自带」，**不能取消**（要改只能改角色） |
   | **额外授权** | 负责人在「用户管理 → 授权」里多勾的权限，存在 `users.extra_permissions` |
   | **有效权限** | 上面两者的并集；`admin` 永远等于全部权限码 |

3. **UI 隐藏 ≠ 安全**  
   前端 `v-if` 只影响展示；**接口必须** `require_permissions` 或服务内再判。

## 1. 角色一览（谁是谁）

| 角色 code | 界面名称 | 定位 |
|-----------|----------|------|
| `admin` | 负责人 | 全机构最高权限，用户管理、调配、纠错 |
| `operator` | 运营 | 获客、内容运营、报名收费；**只看自己相关**订单/课消；**不能改学员档案** |
| `teacher` | 老师 | 素材、名下相关学员只读、课表、录学情 |
| `cr` / `academic_manager` | CR（班主任/学管） | 名下学员教务+财务；可编辑学员；可报名 |

## 4. 数据范围（同一权限码，看到的数据不同）

权限码只决定「能不能进模块」；**范围**在服务层：

| 角色 | 学员列表 | 订单 | 课消 | 报名可操作学员 |
|------|----------|------|------|----------------|
| 负责人 | 全机构 | 全机构 | 全机构 | 全机构 |
| 运营 | 全机构只读（可看档案） | **本人业绩/创建** 或 **本人相关学员**（建档人 / 来源线索主责） | **本人相关学员** | 本人相关学员 |
| CR/学管 | **名下** `academic_manager_id=自己` | 名下学员 | 名下学员 | 名下学员 |
| 老师 | 有 read 可进；电话脱敏 | 无 finance 默认 | 无 | 无 |

实现：`roles.managed_student_ids` / `operator_related_student_ids` + `finance` 服务过滤。

## 5. 关键按钮 / 操作 ↔ 权限

### 5.1 学员

| 操作 | 需要权限 | 运营默认 |
|------|----------|----------|
| 进列表/详情 | `students.read` | ✅ 可看 |
| 列表「编辑」、详情「编辑档案」 | `students.write` | ❌ **不可** |
| 删除 / 转交学管 | `students.delete` | ❌ |
| 课包改/结课等 | `students.write` | ❌ |
| 去报名 / 续费 | `enrollments.manage` | ✅ |
| 录学情 | `learning.write`（部分 UI 仍混有角色判断，逐步统一） | ❌ |

### 5.2 线索

| 操作 | 需要权限 | 备注 |
|------|----------|------|
| 列表/详情 | `leads.read` | |
| 新建/跟进/改状态 | `leads.write` | **已报名**后锁定：跟进/协作全员禁；状态仅 **负责人** 可改 |
| 改已报名 → 跳转报名 | `enrollments.manage` | 有报名权才自动跳转 |

### 5.3 财务

| 操作 | 需要权限 | 运营默认 |
|------|----------|----------|
| 订单列表/详情 | `finance.read` | ✅ 仅自己相关 |
| 课消列表/详情 | `finance.read` | ✅ 仅自己相关学员 |
| 报名提交 | `enrollments.manage` | ✅ |
| 筛选项：课程/班级/老师目录 | `finance.read` **或** `enrollments.manage` **或** `academic.*` | ✅ 只读目录，不开放教务菜单 |

### 5.4 用户管理（负责人）

| 操作 | 说明 |
|------|------|
| 列表「额外权限 +N」 | 只统计 **不在角色自带里** 的 extra（与弹窗一致） |
| 授权弹窗「角色自带」 | 勾选且锁定，保存时不会写入 extra |
| 授权弹窗可勾选的 | 真正的额外码；保存后用户需重新登录才刷新前端缓存时，以 `/auth/me` 为准 |

## 6. 按角色「能做什么」速查（产品视角）

### 6.1 负责人 `admin`

- 全部菜单与按钮  
- 用户管理、额外授权  
- 线索已报名纠错、学管调配  
- 全机构财务/教务  

### 6.2 运营 `operator`（当前默认）

**能：**

- 线索跟进 → 标已报名 → 自动建档 → 报名收费  
- 看学员列表/详情（**不能编辑档案**）  
- 看**自己相关**订单、课消  
- 素材/文案/海报/生图/知识库只读/模板/办公表  

**不能（除非额外授权）：**

- 编辑/删除学员、转交学管  
- 完整教务（班级课表排课点名）  
- 收支明细、充值、收入报表  
- 用户管理、改知识库条目  

### 6.3 老师 `teacher`

- 素材、学员只读（无电话）、课表、录学情  
- 默认无获客/财务/运营内容生成  

### 6.4 CR / 学管 `cr`

- 线索、名下学员（含编辑）、教务写、报名、名下财务  
- 无用户管理、无课程目录增删、无收入报表（除非额外授权）

## 7. 额外授权怎么用（负责人操作说明）

1. 打开 **用户管理** → 某用户 → **授权**  
2. 弹窗顶部：`角色自带 N 项 | 额外授权 M 项`  
3. 带「角色自带」标签的项 = 改不了，属于该角色包  
4. 其它勾选 = 额外授权，点 **保存授权** 写入  
5. 用户 **重新登录** 后菜单/按钮按新有效权限生效  

**两个同角色用户权限不同的常见原因：**

- 一个被勾过额外权限，一个没有  
- 历史 extra 里曾写入后来并入「角色自带」的码（列表曾显示 +1、弹窗 0；现已统一只计真正额外）

## 8. 开发改权限检查清单

改默认包或新功能时：

1. [ ] 在 `permissions.py` 的 `PERMISSION_DEFS` 增加/改文案  
2. [ ] 更新对应角色 `_OPERATOR` / `_TEACHER` / `_CR`  
3. [ ] 同步 `frontend/src/constants/permissions.ts`  
4. [ ] 路由 `meta.permissions`、菜单 `useAppMenus`、按钮 `hasPermission`  
5. [ ] 后端 `require_permissions` + **数据范围**（若跨人）  
6. [ ] 更新本文表格  
7. [ ] 相关账号重新登录验证  

**禁止：**

- 只给 `academic.read` 给运营「顺便选课」→ 会整组教务菜单出现（已改为目录接口认 `enrollments.manage` / `finance.read`）  
- 列表编辑按钮不判 `students.write`（已修）  
- 仅前端隐藏写按钮、接口不校验

## 9. 目录接口（特殊放行）

下列 **GET 只读目录** 使用「多码任一」：`academic.read | academic.write | enrollments.manage | finance.read`

- `GET /academic/courses`  
- `GET /academic/courses/{id}`  
- `GET /academic/teachers`  
- `GET /academic/classes`（课消筛选项等）  

**写接口**仍只要 `academic.write` / `academic.courses_admin`，运营默认进不去。
