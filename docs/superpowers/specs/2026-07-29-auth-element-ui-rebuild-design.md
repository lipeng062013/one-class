# 登录完善与 Element Plus 前端重建 — 设计规格

**日期：** 2026-07-29  
**状态：** 已与用户确认（同意）  
**父规格：** `docs/superpowers/specs/2026-07-28-one-class-ops-platform-design.md`  
**实施方式：** 方案 A — 先登录 + 用户管理，再按模块用 Element Plus 铺业务页  

---

## 1. 背景与问题

壹号教室运营工具平台 V1 已有整体设计与实现计划，但仓库中 **尚无** 可运行的 `frontend/`、`backend/`。当前仅有运营手册 HTML 与文档。

用户反馈的核心问题：

1. **其他角色账号登录不了 / 不清楚密码**  
   - 负责人可添加运营等账号，但若建号时未强制设置、展示初始密码，对方无法登录。  
   - 种子演示账号的用户名与密码必须写进文档与登录页提示，避免「只有 admin 能登」的错觉。

2. **需要忘记密码机制**  
   - 机构内部工具，V1 **不接短信/邮箱**。  
   - 采用 **管理员重置密码**；登录页提供说明入口。

3. **用 Element UI 体系重建页面**  
   - 指 **运营工具平台**（登录、素材、文案等），不是运营手册 HTML。  
   - Vue 3 使用 **Element Plus**（Element UI 的 Vue 3 对应方案）；全站响应式。

本规格补充/细化父规格中的认证与前端 UI 部分，并规定 **优先交付顺序**。

---

## 2. 目标与非目标

### 2.1 目标

- 完整的 **账号 + 密码** 登录（三角色：admin / operator / teacher）。
- 负责人 **新建用户必须设置初始密码**；创建成功后 **仅展示一次** 可复制的账号与密码。
- **管理员重置密码**（忘记密码的实际处理路径）。
- 登录用户可 **修改自己的密码**。
- 登录页提供 **「忘记密码」说明**（联系负责人在用户管理中重置）。
- 前端以 **Element Plus** 统一重建；先登录/用户/改密，再业务模块。
- 开发环境 **幂等种子账号**，默认密码可配置并在 README / 登录页演示区写明。

### 2.2 非目标（V1 不做）

- 短信 / 邮箱自助重置、OAuth、扫码登录。
- 首次登录强制改密（`must_change_password`）— 明确延后；若后续需要可再开规格。
- 改造 `one-class-operations-guide.html` 为 Element 风格。
- 多因素认证、密码历史策略、复杂密码强度策略（仅最低长度）。

## 3. 登录与账号密码设计

### 3.1 登录

| 项 | 约定 |
|----|------|
| 方式 | 用户名 + 密码 |
| 成功 | 返回 JWT（access token）+ 当前用户摘要（id、username、display_name、role） |
| 失败 | 统一提示「账号或密码错误」（不区分用户是否存在） |
| 停用账号 | `is_active=false` 时拒绝登录，提示「账号已停用，请联系负责人」 |
| 角色跳转 | admin/operator → 工作台 `/`；teacher → `/m/upload` |

### 3.2 种子（演示）账号

应用启动时 **幂等** 写入（已存在则不覆盖密码）：

| 用户名 | 默认密码 | 角色 | 说明 |
|--------|----------|------|------|
| `admin` | `admin123` | admin | 负责人 |
| `ops` | `ops123` | operator | 运营 |
| `teacher1` | `t123` | teacher | 老师 |

- 默认值可通过环境变量覆盖（如 `SEED_ADMIN_PASSWORD`），**禁止** 把生产真实密码写进仓库。  
- **README-ops-platform** 与登录页「演示账号」折叠区写明上述三组（仅开发/演示用途提示）。  
- 生产部署必须修改默认密码或关闭演示提示、改用自建账号。

### 3.3 新建用户（仅 admin）

表单字段：

- `username`（必填，唯一）
- `display_name`（必填）
- `role`：`admin` | `operator` | `teacher`（必填）
- `password`（**必填**，最短 6 位）
- 可选 UI：**生成随机密码** 按钮（填入密码框，仍可改）

创建成功后：

1. 后端只存 `password_hash`，**永不** 在列表/详情接口返回明文或 hash。  
2. 前端弹窗展示 **仅一次**：用户名、角色、初始密码；提供一键复制。  
3. 关闭弹窗后无法再查看该明文；遗忘则走「重置密码」。

### 3.4 忘记密码 = 管理员重置

- 登录页「忘记密码」：`el-dialog` 或抽屉说明：  
  > 本系统为机构内部工具，请联系 **负责人**，在「用户管理」中为您 **重置密码**。重置后负责人会把新密码告知您。  
- 用户管理（admin）：对目标用户操作 **重置密码**  
  - 填写新密码或「生成随机密码」  
  - 提交后弹窗 **仅展示一次** 新密码，可复制  
- 不发送邮件/短信。

### 3.5 修改自己的密码

- 入口：顶栏用户菜单 →「修改密码」（所有已登录角色）。  
- 字段：当前密码、新密码、确认新密码。  
- 校验：当前密码正确；新密码 ≥6；两次一致。  
- 成功后提示成功；可选要求重新登录（V1：改密成功后保持当前会话亦可，实现选「保持会话 + 成功提示」即可）。

### 3.6 用户列表与启停

- admin 可列表查看：用户名、显示名、角色、是否启用、创建时间。  
- admin 可启停账号（`is_active`）；不可在列表中看到密码。  
- V1 可不提供「删除用户」，以停用代替（避免外键孤儿）；若实现删除须处理关联策略，默认 **仅停用**。

## 4. 数据与 API

### 4.1 users 模型（相对父规格无破坏性变更）

- `id`, `username`, `password_hash`, `display_name`
- `role`: `admin` | `operator` | `teacher`
- `is_active`, `created_at`
- 密码仅存 hash（bcrypt 或等价）

### 4.2 API（前缀 `/api/v1`）

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/auth/login` | 公开 | `{ username, password }` → token + user |
| GET | `/auth/me` | 登录 | 当前用户 |
| POST | `/auth/change-password` | 登录 | `{ current_password, new_password }` |
| GET | `/users` | admin | 用户列表（无密码字段） |
| POST | `/users` | admin | 建号，body **必含** `password` |
| PATCH | `/users/{id}` | admin | 更新 display_name / role / is_active（**不含** 直接改密码） |
| POST | `/users/{id}/reset-password` | admin | `{ new_password }` 重置 |

响应信封与父规格一致：`{ "data": ..., "error": null }`；错误含 `code` / `message`。

**安全：**

- 登录失败不枚举用户名。  
- 重置/建号的明文密码只在 **创建或重置请求的前端内存** 中展示，API **不** 在响应里回传 password（前端用用户刚提交的值展示弹窗即可）。  
- JWT 密钥仅环境变量。

## 5. 前端（Element Plus）重建

### 5.1 技术

- Vue 3 + TypeScript + Vite + Vue Router + Pinia  
- **Element Plus** + `@element-plus/icons-vue`  
- 响应式：桌面侧栏；窄屏抽屉/折叠；老师端 `MobileLayout`

### 5.2 优先交付页面（第一批）

1. **登录页** `/login`  
   - `el-form`：用户名、密码、登录按钮  
   - 忘记密码说明  
   - 开发环境可展示演示账号折叠面板（`import.meta.env.DEV` 或配置开关）  
2. **后台壳** `AppLayout`：侧栏 + 顶栏 + 用户下拉（改密、退出）  
3. **用户管理** `/users`（admin）：表格、新建对话框、重置密码对话框、启停  
4. **修改密码** 对话框或 `/profile/password`  

### 5.3 后续业务页（第二批起，同一套 Element 风格）

工作台、素材、文案、海报、线索、知识库、模板、老师手机上传/我的素材。  
禁止业务页退回无样式原生 HTML 表单作为主 UI。

### 5.4 与手册关系

- `one-class-operations-guide.html` **保持独立**，不纳入 Element 重建范围。

## 6. 实施顺序（方案 A）

1. 后端骨架：配置、DB、User、密码哈希、JWT、health  
2. 认证：login、me、change-password、seed 三账号  
3. 用户管理 API：list、create（必填密码）、reset-password、patch is_active  
4. 前端脚手架 + Element Plus 全局注册  
5. 登录页 + 路由守卫 + 改密  
6. 用户管理页（建号弹窗一次展示密码、重置一次展示）  
7. 再按父规格实现其余业务模块 UI 与 API  

---

## 7. 验收标准

1. 使用种子账号 `ops/ops123`、`teacher1/t123` 可分别登录并进入对应默认页。  
2. admin 新建运营账号时 **不填密码无法提交**；填密码成功后弹窗可复制账号密码，用该密码可登录。  
3. 登录页有「忘记密码」说明；admin 重置密码后弹窗展示新密码，对方可用新密码登录、旧密码失效。  
4. 任意登录用户可成功修改自己的密码。  
5. 登录、用户管理、改密界面均为 Element Plus 组件，桌面与窄屏可完成主操作。  
6. 用户列表/ me 接口响应中 **无** 明文密码或 password_hash。  
7. 仓库与 `.env.example` 无真实生产密钥。

## 8. 决策记录

| 主题 | 决定 |
|------|------|
| 忘记密码 | 管理员重置 + 登录页说明；无邮件/短信 |
| 建号密码 | 必填初始密码；成功弹窗展示一次 |
| 强制首次改密 | V1 不做 |
| UI | Element Plus；先认证/用户再业务页 |
| 重建范围 | 运营工具平台，不含手册 HTML |
| 删除用户 | V1 以停用代替 |
